# SkillSwap Campus: Backend Foundation Documentation
## Phase 3: Backend Setup & Foundation

This documentation outlines the directory layout, configuration structure, startup steps, local development commands, and setup checklists for the backend of **SkillSwap Campus**.

---

## 1. Project Folder Structure

The project directory structure is laid out as follows:

```
skillswap-campus/
│
├── backend/
│   ├── app/
│   │   ├── config/
│   │   │   └── config.py        # Config loader class (reads environment variables)
│   │   ├── models/
│   │   │   ├── __init__.py      # Imports models to support Flask-Migrate autodetect
│   │   │   ├── availability.py  # UserAvailability database model
│   │   │   ├── review.py        # Review database model
│   │   │   ├── session.py       # SwapRequest & Session database models
│   │   │   ├── skill.py         # Skill & UserSkill database models
│   │   │   ├── transaction.py   # CreditTransaction database model
│   │   │   ├── user.py          # User database model
│   │   │   └── utility.py       # Notification & AuditLog database models
│   │   ├── routes/
│   │   │   └── health.py        # /health health check route blueprint
│   │   ├── services/            # (Empty for now) Holds business logic handlers
│   │   ├── utils/               # (Empty for now) Holds system helper logic functions
│   │   ├── __init__.py          # Flask application factory (create_app)
│   │   └── extensions.py        # Extension instances (db, migrate)
│   │
│   ├── migrations/              # Database migration version files (autogenerated by Flask-Migrate)
│   ├── requirements.txt         # Project package dependencies
│   ├── run.py                   # Dev server run script
│   └── .env.example             # Template for local environment configs
│
├── frontend/                    # Vanilla Web Interface assets (to be added in later phases)
│
└── docs/                        # Architectural diagrams and blueprints documentation
```

### Folder Explanations

* **`backend/app/__init__.py`**: Contains the **application factory pattern** logic (`create_app()`). This initializes configuration files, binds SQLAlchemy and Flask-Migrate extensions to the app instance, registers route blueprints, and enables CORS mappings.
* **`backend/app/config/`**: Contains runtime application configurations. Loads `.env` inputs and defines system fallback values.
* **`backend/app/extensions.py`**: Declares instances of third-party libraries (SQLAlchemy, Migrate) separately from the application factory to resolve circular import chains.
* **`backend/app/models/`**: Holds database ORM models mapped to the PostgreSQL architecture designed in Phase 2.
* **`backend/app/routes/`**: Contains route blueprint divisions. Currently contains the health checking route.
* **`backend/app/services/`**: Formulated to hold business logic modules (e.g., matching calculators, transaction ledgers) in upcoming phases, keeping routes simple.
* **`backend/app/utils/`**: Intended for static utility functions (e.g., email validation helpers, datetime format convertors).

## 2. Dependency Explanations

Here are the key dependencies defined in `backend/requirements.txt`:

* **`Flask`**: A WSGI web application framework chosen for its lightweight design.
* **`Flask-SQLAlchemy`**: Links SQLAlchemy's SQL toolkit and Object Relational Mapper to Flask applications.
* **`Flask-Migrate`**: Handles database migrations using Alembic, allowing database alterations without losing tables.
* **`psycopg2-binary`**: The PostgreSQL database driver adapter for Python.
* **`python-dotenv`**: Loads local configuration key-value variables from a `.env` file into application environment mappings.
* **`Flask-Cors`**: Manages Cross-Origin Resource Sharing (CORS) headers, which is necessary when connecting the backend API to a standalone frontend.
* **`bcrypt`**: Used for hashing password strings securely during login and registrations.

## 3. Startup & Local Development Steps

### Step 3.1: Python Environment Creation
1. Navigate to the backend directory:
   ```bash
   cd backend
   ```
2. Build a virtual environment to isolate python dependencies:
   ```bash
   python -m venv venv
   ```
3. Activate the environment:
   * **Windows PowerShell**:
     ```powershell
     .\venv\Scripts\Activate.ps1
     ```
   * **macOS/Linux Terminal**:
     ```bash
     source venv/bin/activate
     ```

### Step 3.2: Install Requirements
```bash
pip install -r requirements.txt
```

### Step 3.3: Configuration Setup
1. Copy the environment config template file:
   ```bash
   cp .env.example .env
   ```
2. Edit the `.env` file and replace the `DATABASE_URL` with your local PostgreSQL database credentials.

### Step 3.4: Initialize Database & Run Migrations
Before executing server startup, initialize the migration manager and apply database layouts:
1. Initialize migrations:
   ```bash
   flask db init
   ```
2. Generate migration version files:
   ```bash
   flask db migrate -m "Initialize database schema"
   ```
3. Apply migration changes to your PostgreSQL instance:
   ```bash
   flask db upgrade
   ```

### Step 3.5: Start Development Server
```bash
python run.py
```
The server will boot and listen by default at `http://127.0.0.1:5000/`.

### Step 3.6: Verify Health Check Endpoint
Query the server to confirm database connectivity:
```bash
curl http://127.0.0.1:5000/health
```
**Expected Response:**
```json
{
  "status": "ok",
  "database": "connected"
}
```

### C. Possible Risks
1. **PostgreSQL Version Discrepancies**: Different PostgreSQL versions can cause data type mapping issues (e.g. enum types or time field behaviors). Solution: Use standard datatypes or handle them in migrations.
2. **Missing Database Driver Binaries**: Installing `psycopg2` from source can fail on some machines due to missing compiler headers. Solution: We use `psycopg2-binary` to avoid compiling issues.
3. **Database Connectivity Failures**: Attempting to run migrations before PostgreSQL is running or before database creation will trigger connection errors. Solution: Ensure the target database exists in PostgreSQL before running `flask db upgrade`.

### D. Required Software Installation
* **Python 3.10+**: Runtime interpreter.
* **PostgreSQL (v14+)**: Target database server.
* **curl / Postman**: For API verification.
